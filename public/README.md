# 개정 예정 법령 검토 대시보드

`index.html` 하나로 된 정적 페이지. 빌드 도구 없이 브라우저에서 Firebase Firestore의
`pendingAmendments` 컬렉션을 직접 읽어 카드로 보여준다. 데이터는 GitHub Actions
파이프라인(`functions/`)이 채워 넣는다 — 이 페이지는 읽기만 한다.

## 사용 전 설정 2가지

### 1. Firebase 클라이언트 설정 채우기

`index.html` 안의 `firebaseConfig` 객체를 실제 값으로 바꾼다. Firebase 콘솔 →
프로젝트 설정(⚙️) → 일반 탭 → "내 앱"에 앱이 없으면 `</>`(웹) 아이콘으로 하나
추가하고, 표시되는 `firebaseConfig` 값을 그대로 복사해 넣으면 된다.

이 값은 비밀값이 아니다 — 브라우저에 그대로 노출되어도 안전하다(Firebase는 이
설정을 공개 웹 앱에 그대로 심어 쓰도록 설계되어 있다). 접근 제어는 아래 Firestore
보안 규칙이 담당한다.

### 2. Firestore 보안 규칙 적용

저장소 루트의 `firestore.rules` 내용을 Firebase 콘솔 → Firestore Database → 규칙
탭에 붙여넣고 "게시"한다. `pendingAmendments`는 읽기 전용으로 공개하고, 쓰기는
GitHub Actions의 서비스 계정(Admin SDK, 규칙을 우회함)만 할 수 있게 막는다.

이 규칙을 적용하지 않으면 기본값(모두 거부)이라 대시보드가 "불러오기 실패"만
표시하게 된다.

## 로컬에서 미리 보기

`file://`로 직접 열면 ES 모듈 import가 브라우저 보안 정책에 막힐 수 있으니 간단한
로컬 서버로 띄운다:

```bash
cd public
npx serve .
# 또는: python3 -m http.server 8080
```

## 화면 구성

- 상단 탭: 전체보기 + 5개 감시 대상 법령(시행령/시행규칙은 법령명 접두어로 자동 묶임)
- 검색창 + 칩 필터: 전체 / 시행임박(D-30 이내) / 요약완료 / 처리대기
- 카드: 법률·시행령·시행규칙 표시, 처리상태 배지, 조문번호·제목, 공포일·시행예정일·D-day,
  Gemini 요약(조문별), "현행/개정 조문 비교" 토글(펼치면 조문별 현행·개정 본문)
- 정렬: 시행예정일이 가장 빠른 건이 맨 위 (시행일 임박순)
- "새로고침" 버튼(우측 상단 아이콘, 필터 바 버튼 둘 다 동일): **Firestore를 다시
  읽기만 한다.** 파이프라인을 지금 바로 다시 돌리고 싶으면 GitHub 저장소의
  Actions 탭에서 `Amendment Pipeline` 워크플로를 수동으로 실행한다.

## 파이프라인이 아직 안 채운 데이터 처리

STEP 2~6가 문서를 점진적으로 채우기 때문에(감지만 됨 → 변경조문 추출됨 → 본문
조회됨 → 요약됨), 카드는 각 단계가 비어 있으면 "변경 조문 추출 대기 중" 같은
안내 문구를 대신 보여준다.
